Data flow

  1. Filter change. The user picks Time Period, Warehouse, Category or Order Status in FilterBar. These four values live in the shared useFilters composable.
  2. Watcher fires. A view such as Dashboard.vue watches the filter refs and reloads its data.
  3. API call. api.js turns the filters into query params (skipping all) and issues several GETs in parallel with axios.
  4. Server filtering. FastAPI handlers run apply_filters and filter_by_month over the in-memory lists loaded from JSON.
  5. Validation. Results pass through Pydantic response_models and return as JSON.
  6. Reactive rendering. Raw responses are stored in refs (allOrders, inventoryItems). Charts, KPIs and tables are computed values derived from them.

Conventions

  • Views in client/src/views, modals in components
  • Unique keys in v-for (sku, month), never index
  • Inventory filters ignore month (no time dimension)
  • Palette: slate/gray with green/blue/yellow/red status colors

Things worth knowing

Observations from reading the code, not from running every feature:
  • api.js calls /api/tasks and /api/purchase-orders, but main.py defines no routes for them (only the Pydantic models). Those features will 404 until the endpoints are added.
  • There is a Backlog.vue view, but no /backlog route is registered in main.js. Backlog data is shown via dashboard panels and modals.
  • Data is read-only and loaded once at startup. Any write would live only in memory and reset on restart.
  • The API base URL (http://localhost:8001/api) is hard-coded in api.js.
  • The current user in useAuth.js is mock data. There is no real authentication.
